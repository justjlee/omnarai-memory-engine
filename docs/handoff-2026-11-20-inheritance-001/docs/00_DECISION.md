# Decision memo — build the instrument, not another archive

## Recommendation

**GO: build a hermetic Inheritance Experiment 001 harness and a reproducible research workflow as an additive part of Omnarai's existing repository.** Do not create a new top-level memory engine or imply an `omnarai_inheritance` endpoint is missing. It already exists as a dynamic read surface. The missing capability is rigorous *causal evaluation* of the extent to which specific verified artifacts help future, different models.

## What Claude improved

Claude's public response adds the essential verification boundary (the pawl of the ratchet) and strengthens the design through:

- compute-matched A+ (charge the creation of curated artifacts to C, amortized transparently)
- structure-matched unrelated-domain placebo E
- raw historical B, evaluated C, contamination D and bare A
- held-out task categories and sealed evaluation set
- distinct model families, sequential generations and leave-one-artifact-out analysis
- a verification-cost gradient; claimed gains should be measured against the cost of checking the work

It also correctly identifies prior work with overlapping concepts. The new contribution must be narrower: **cross-model, cross-generation, provenance-linked, contamination-resistant, compute-accounted inheritance**.

## One additional correction from Omnai

Claude proposes `G(n+1) > G(n)` across several generations. We should **not** treat a visually increasing line as sufficient. Preregister the unit of analysis, uncertainty intervals, multiplicity plan and a strict distinction between cumulative transfer and simple retrieval advantage. A condition C lead against A+ on novel tasks is evidence for *inheritance benefit*; a reproducible positive trend over linked generations, where contributions really came from earlier experimental work, is stronger evidence for *cumulative improvement*. Neither establishes generalized or open-ended intelligence growth.

## Initial vertical slice

A fixture-based, zero-spend experiment proving that the plumbing can:

1. create sealed tasks and immutable snapshots
2. assign A/A+/B/C/D/E without contamination
3. ensure generation N never reads N or later work
4. expose all arms to comparable formatting and audited budgets
5. record exact model/source/run relationships
6. score with hidden deterministic oracles
7. compute paired treatment effects, uncertainty and ablations
8. report **null or negative results without suppressing them**

Then—and only with spend approval—replace the mock solver with real provider adapters and run an explicitly limited, preregistered pilot.

## Do not misstate the achievement

The presence of Footprints, a trace endpoint, a claims registry, and an inheritance read API is infrastructure. It is not a randomized controlled inheritance experiment. Conversely, a successful isolated pilot would not prove a general theory of intelligence.

## Decision constraints

- Research code may be developed freely on a feature branch; public claims, external spending, and production deployment remain gated.
- All primary contributions are preserved as authored; evaluations and redactions are independent, append-only records.
- Curator approval cannot be delegated to a score-producing model.
- No mass importing experimental entries into the public corpus.
- Respect Vercel Hobby 12-function cap and existing deployment procedure.
