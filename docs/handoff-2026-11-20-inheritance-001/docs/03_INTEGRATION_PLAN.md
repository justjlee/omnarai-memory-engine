## Phase 1 — research namespace and schema (read-only/fixture-only)

Suggested additive layout in **engine repo**, adaptable to conventions:

```
research/inheritance-001/
  PROTOCOL.md
  preregistration.yaml  # frozen before live runs; changes tracked in deviations
  deviations.ndjson
  README.md
  fixtures/            # public synthetic smoke only
  sealed/              # PRIVATE local/gitignored or encrypted storage; no secret keys in repo
  snapshots/           # content hashes and manifest only
  results/             # immutable per-run events (private until review)
  reports/             # derived, repeatable, honest summaries
scripts/inheritance-001/
  plan.mjs              # pure; deterministic arm/block assignments
  validate.mjs          # schema, collisions, prior-generation gate
  snapshot.mjs          # freeze exact material and provenance
  run-offline.mjs       # deterministic fake model, no network
  run-models.mjs        # NOT allowed without --yes, policy and budget preflight
  verify.mjs            # independent tool tests, no model grader on primary tasks
  summarize.mjs         # pre-registered estimands and CIs; flags null/negative
  ablate.mjs            # bounded per-artifact perturbation
  lib/...               # adapters for existing Footprints and Lab data
```

Do not write raw experimental memory into `memory/grown.json`. Do not bypass `api/_footprints.js` or change Footprint schema to hold study-specific fields. Prefer *external experiment records that cite Footprint primary IDs* (and their manifest/snapshot hashes). Experiment artifacts can exist without becoming public Footprints.

### Proposed draft artifact concepts

- **Task family**: generator version/hash, hidden oracle, domain, verification cost, contamination class.
- **Experiment contribution**: immutable, authored text/code/strategy, exact provider model, task provenance, generation, independent evaluation receipts, input snapshot hash, source refs/relationships, content hash; state `proposed|evaluated|rejected|superseded`, never inferred truth.
- **Snapshot**: immutable ordered artifact IDs + hashes, allowed generations, policy version, digest. A query references a specific snapshot, not "latest".
- **Trial**: condition, task ID, consumer model, generation, seed, prompt and context digests, raw response sealed locally, scoring receipt, token/cost/latency, exact run status.
- **Ablation**: causal pair `(full snapshot, snapshot-minus-i)` evaluated under the same task/model/seed block.
- **Report**: derived solely from sealed trial events and the preregistered analysis script. Never self-certified by the consumer model.

## Phase 2 — hermetic integration with existing local engine

Run the actual engine handlers under `node --import ./scripts/lib/register-mem-blob.mjs ...` or the current equivalent. Unit tests should seed Footprints and reviews, use an offline read adapter to export admitted primaries, and assert that pending/rejected/redacted events are not treated as validated input. Use the *review state* for eligibility, not a claim of truth. Require independent verification receipts in addition to curator admission.

Tests should exercise:

- snapshot construction, stable hashes, expiry and ID exact-match
- no same-generation or future-generation access
- no private receipts, reviewer notes or bearer IDs in model prompts or logs
- raw records B vs evaluated records C vs irrelevant placebo E
- D's misleading material is included as **data** with prompt-injection strings denied any tool authority
- duplicate artifact identity, review conflicts, falsified evaluation receipts fail closed
- CPU/network sandboxes never run submitted code in the Vercel request lifecycle
- output reports can be fully regenerated byte-for-byte from a frozen snapshot

## Phase 3 — model adapter (offline smoke first, spend-gated live pilot)

Provider adapters must expose an honest call record:

```
call({provider, model_id, input, temperature, seed_if_supported, max_output_tokens,
      timeout_ms, allowed_tools, spending_cap, tracing_id})
 -> {provider_returned_model_id, output, usage, cost_estimate, request_id,
     provider_response_metadata, duration_ms, error}
```

**Do not claim deterministic responses because a seed was supplied**; provider defaults and hidden model refreshes can change behavior. Pin model identifiers and date, and store raw usage. Retries are explicit attempts with unique IDs, not silent overwrites. Where provider pricing is not machine-accessible, put cost in `unknown` and refuse to label A+ compute-matched.

The `--yes` flag alone is insufficient: require experiment name, per-provider maximum cost, a specific finite call cap, and a dry-run preview. Do not run anything chargeable on the first implementation pass.

## Phase 4 — evaluate, report and decide

- Generate plan manifest/checksums; freeze before responses.
- Run tiny fixture smoke test and a fully offline reproducibility pass.
- Present anticipated costs and model choices to Yonotai before live experimental spend.
- Execute approved pilot in private workspace; blind scoring; manual/automated audit.
- Produce `results.jsonl`, `summary.json`, `REPORT.md`, `deviations.ndjson`, a blinded error gallery, costs and code commit hashes.
- Mark `evidence_status: exploratory` until confirmatory replication.
- **No automatic promotion** of results to Omnarai claims registry or corpus. Curator reviews and authorizes any public claim or production exposure.

## Phase 5 — only if the pilot earns integration

Add a **read-only** research-results discovery surface, ideally folded into an existing function without exceeding Vercel cap. Before changing MCP tools, check `contract.js`, `_contract.js`, `check-tool-contract.mjs`, `check-mcp-surface.js`, `check-response-envelope.mjs`, `public/openapi.json`, and associated client compatibility. Separate protocol `omnarai.inheritance-study/1.0` from existing `omnarai.response/1.0` and Footprint/1.x. Keep any public data aggregated; sealed tasks and grading oracles stay private.

## Compatibility stop conditions

Stop and seek decision if implementation demands rewriting immutable primaries, bypassing review, exposing sealed data, weakening trust-boundary language, turning a read tool into a write tool, changing production without approval, or creating an unbudgeted paid multi-model loop.
